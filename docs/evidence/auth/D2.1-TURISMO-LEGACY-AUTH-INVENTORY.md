# D2.1 — Turismo legacy auth inventory

**Data:** 2026-06-22 (atualizado pós D2.2/D2.3)  
**Gap:** AUTH-ALIGNMENT-MATRIX D2

## Resumo

O turismo usa **v1** para login/session/refresh/logout/register (`AUTH_V1` em `lib/auth-v1.ts`).

**2FA** e **forgot/reset** permanecem defer no cliente (`auth-legacy-deferred.ts`) — backend legado `/api/auth/*` retorna **404**.

## Inventário de callers

| Endpoint | Arquivo turismo | Backend `:3002` | Status |
|----------|-----------------|-----------------|--------|
| `POST /api/v1/auth/login` | `authService.ts` | 200/401 | ✅ v1 |
| `GET /api/v1/auth/session` | `authService.getCurrentUser` | 200/401 | ✅ v1 |
| `POST /api/v1/auth/refresh` | `authService.refreshToken` | 200/401 | ✅ v1 |
| `POST /api/v1/auth/logout` | `authService.logout` | 200 | ✅ v1 |
| `POST /api/v1/auth/register` | `authService.register`, `AuthContext` | 201/409 | ✅ v1 (D2.3) |
| `POST /api/auth/2fa/*` | `authService` (defer) | **404** | ⏸ defer |
| `POST /api/auth/forgot-password` | `authService` (defer) | **404** | ⏸ defer |
| `POST /api/auth/reset-password` | `authService` (defer) | **404** | ⏸ defer |
