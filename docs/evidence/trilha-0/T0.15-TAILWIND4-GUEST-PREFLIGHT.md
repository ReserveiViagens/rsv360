### Passo 2 — Dependências (escopo guest + lock root)

| Pacote | Ação |
|--------|------|
| `tailwindcss` | → **4.x** estável |
| `@tailwindcss/postcss` | **adicionar** (devDep guest ou root workspace hoist) |
| `autoprefixer` | **remover** do guest se TW4 cobrir prefix (validar build) |
| `postcss` | manter **8.5.15** override root — **não downgrade** |

Ferramenta sugerida (Node ≥20):

```bash
cd apps/guest
npx @tailwindcss/upgrade
```

Revisar diff manualmente — especialmente `darkMode` e tokens `brand`.

### Passo 3 — Alterações esperadas

| Arquivo | Ação |
|---------|------|
| `apps/guest/styles/globals.css` | `@import "tailwindcss";` + bloco `@theme` com cores `brand` e `--shadow-soft` |
| `apps/guest/postcss.config.js` | plugin `@tailwindcss/postcss` |
| `apps/guest/tailwind.config.ts` | **remover** ou reduzir a `@config` fallback (preferir CSS-first) |
| `apps/guest/package.json` | versões TW4 |
| `package-lock.json` | regenerar escopo guest |

**Não alterar:** `next.config.js` (`serverExternalPackages`, webpack build), `Dockerfile`, admin, outros apps.

### Passo 4 — Migração `darkMode: 'class'`

TW4 não lê `darkMode` do JS config. Migrar para CSS:

```css
@custom-variant dark (&:where(.dark, .dark *));
```

Validar se guest usa classe `.dark` no DOM (layout) — hoje config prepara dark mode; confirmar uso real antes do merge impl.

### Passo 5 — Tokens `brand` / `shadow-soft`

Migrar de `theme.extend` para `@theme`:

```css
@theme {
  --color-brand-50: #f8fafc;
  /* ... brand-900 ... */
  --shadow-soft: 0 18px 45px rgba(15, 23, 42, 0.08);
}
```

Classes existentes `bg-brand-900`, `shadow-soft` devem continuar resolvendo após mapeamento correto.

### Passo 6 — `@apply` (2 regras)

Manter ou converter para utilities explícitas se o upgrade tool falhar — gate = visual smoke `:3006` + build.
