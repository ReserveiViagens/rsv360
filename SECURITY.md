# Política de Segurança

Obrigado por ajudar a manter este projeto seguro.

## Versões suportadas
Este repositório segue boas práticas de atualização contínua. Recomendamos sempre usar a versão mais recente do código na branch principal (main/master) e manter dependências atualizadas.

## Como reportar uma vulnerabilidade

**Não abra issues públicas para relatar vulnerabilidades.**

Envie um relatório **privado** por um dos canais abaixo:

1. **GitHub Private Vulnerability Reporting (recomendado)**
   - Acesse a aba **Security** do repositório e use “Report a vulnerability” (quando habilitado).

2. **E-mail**
   - Envie para: **security@SEU-DOMINIO.com** (substitua pelo e-mail correto)
   - Assunto: `[SECURITY] Vulnerabilidade em <nome-do-repo>`

## O que incluir no relatório
- Descrição do problema e impacto
- Passos para reproduzir
- Prova de conceito (se possível)
- Versão/commit/branch afetados
- Sugestão de correção (se tiver)

## SLA de resposta (referência)
- Confirmação de recebimento: até **72 horas**
- Primeira avaliação: até **7 dias**
- Correção e divulgação coordenada: conforme severidade e complexidade

## Divulgação coordenada
Trabalharemos com você para validar a correção e, quando aplicável, publicar um GitHub Security Advisory (CVE pode ser solicitado via GitHub).
